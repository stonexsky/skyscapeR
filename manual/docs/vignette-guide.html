16  Following the package vignette

W02 records the intermediate tables from the archived and 2.0.9009 Malta workflows, plus independent synthetic field controls.

Use this guide alongside skyscapeR: from field measurements to skyscape analysis, the vignette in the archived 2.0.9004 source. Each entry follows a decision in that workflow to its technical explanation. In R, open the installed vignette with vignette("skyscapeR", package="skyscapeR") when vignettes are installed. The source is vignettes/skyscapeR.Rmd inside the package download in the function methods catalogue.

The opening setup checks for spreadsheet and ephemeris dependencies. Conditional examples may be skipped when the vignette is built without those inputs. The ephemeris chapter identifies the backend and data required for reproducing ancient positions.

16.1 Field data

16.1.1 Import your observations

Read the Compass worksheet with readxl. Keep the original bearing, date, site identifier, latitude, longitude, elevation and measured skyline altitude in the same row. A spreadsheet import is an external R operation. Its column order and units determine what the reduction receives.

Technical explanation.

16.1.2 Reduce compass readings to true azimuth

Pass the location matrix and observation dates in worksheet order. Preserve the raw magnetic readings alongside the declination correction and the returned true bearings.

Technical explanation. reduct.compass(), mag.dec().

16.1.3 Reduce a theodolite survey with a solar sight

The solar limb, local clock and unchanged instrument circle setting identify the reference for the structural bearings. Pair the reduced bearings with their measured horizon altitudes.

Technical explanation. reduct.theodolite(), ten(), sunAz().

16.1.4 Convert each sightline to celestial declination

The measured horizon altitude belongs to the same true bearing and observer latitude. The direct transform gives one declination per row. Uncertainty propagation requires an orientation distribution.

Technical explanation. az2dec().

16.1.5 Which targets fit the measurement?

Screen the two-degree interval around the example measurement over the stated dating interval. The two degrees are a choice in the vignette. The search does not estimate this uncertainty.

Technical explanation. findTargets().

16.2 One site

16.2.1 The doorway at Mnajdra South

The bundled malta_entrances table contains 32 entrances. Its unnamed companion list malta_horizons contains the corresponding profiles generated by Tore Lomsdalen with Andrew Smith’s Horizon software from the Heritage Malta 5 m DEM. Check the stored site metadata after any reordering. Select a named entrance before extracting its edges. The vignette can average these two edge bearings because its opening does not cross north. For a north-crossing opening, take the clockwise width modulo 360° before computing its midpoint.

Technical explanation.

16.2.2 Importing site horizons

Measured profiles, transparent photographs, HeyWhatsThat, PeakFinder and a DEM provide different evidence about the same direction. The bundled Mnajdra skyline is selected by the entrance row index. Read each edge altitude from that profile before transforming the edge.

Technical explanation. createHor(), importPanorama(), createHWT(), importPeakFinder(), exportStellarium(), hor2alt(), az2dec(), plot.skyscapeR.horizon().

16.2.3 Which objects fit the doorway?

Use the declinations of both doorway edges and the monument’s date range. If the skyline has a notch or ridge inside the opening, also inspect the interior, since the extremal declination need not occur at either edge.

Technical explanation. findTargets().

16.2.4 Equinoctial sunrise

A zero-declination reference track and the Sun at its terrain crossing are different astronomical quantities. The equinox occurs at an instant, which can be hours after local sunrise. Retain the returned crossing declination for the dated track.

Technical explanation. riseset(), sketchSky(), skyObject(), plot.skyscapeR.horizon().

16.2.5 The heliacal rising of the Pleiades

Take the event’s local Julian calendar date, compute the terrain crossing on that date, then advance the time to allow the centre to clear the ridge. Integrated M45 and the individual Alcyone use different magnitudes and can receive different phase dates.

Technical explanation. star.phases(), riseset(), time2jd(), sketchSky(), plot.skyscapeR.starphases(), plot.skyscapeR.horizon().

16.2.6 Watch the cluster rise later in the season

Adding 60 days to the earlier JD selects a later date for a new rise calculation. Adding five minutes to a particular crossing, or stepping a reconstructed sky ten minutes, instead changes the displayed instant. Keep the doorway edges and sector fixed across frames.

Technical explanation. riseset(), sketchSky(), skyStep(), plot.skyscapeR.horizon().

16.3 Multiple sites

16.3.1 Start with the Ġgantija entrance bearings

Use the same indices for the entrances and their horizons. Plot centre bearings on the compass and half-widths on the interval plot. A compass solstice mark uses the level-horizon crossing at the supplied site.

Technical explanation. plotAzimuth(), plotBars(), skyObject().

16.3.2 Give each opening a distribution

A uniform azimuth PDF treats the directions between doorway edges as equally probable. Transform each opening across its own skyline before summation. The linked single-site view can show several disjoint intervals at the requested density mass.

Technical explanation. az.pdf(), coordtrans(), spd(), plot.skyscapeR.pdf(), plot.skyscapeR.spd().

16.3.3 Test random orientations

The vignette reads a saved 500-simulation fit. Its lower panel displays separately adjusted excess and deficit clusters. Reading the bundled fit does not run 500 new simulations. Retain the seed, observations and matching skylines to reproduce the fit.

Technical explanation. randomTest(), plot.skyscapeR.sigTest().

16.3.4 Exploring celestial candidates

Filter the positive clusters by adjusted p-value before searching their declination intervals. A compatible Gacrux band is a candidate. Checking its phase and the view from Skorba West asks a separate site-specific question.

Technical explanation. findTargets(), skyObject(), star.phases(), riseset(), time2jd(), sketchSky(), modelTest(), plot.skyscapeR.sigTest(), plot.skyscapeR.horizon().

16.4 Other tools

16.4.1 Compare the three sky styles

Recompute the same horizon and instant in each style. The natural rendering maps a light budget to the display. The two publication styles use symbols to show geometry, even when natural visual contrast is weak.

Technical explanation. sketchSky(), plot.skyscapeR.horizon().

16.4.2 Compare stellar seasons

Pass the first result as x and further results in the second argument. Compare one star across epochs, several stars at one epoch, or a list ordered by star and year. A shared seasonal reference aligns the rows.

Technical explanation. star.phases(), plot.skyscapeR.starphases().

16.4.3 Compare constellation patterns

Keep site, epoch and field fixed while changing modern figures, Chinese mansion asterisms or selected figure identifiers. The bundled constellations table has 88 modern rows, 318 Chinese rows and a separate 28-row mansion selection. Each pair of HIP identifiers is an independent segment. The star.names lookup maps Western names to catalogue identifiers; it does not define the line patterns. The same catalogue star can participate in a different line pattern. Imported legacy HIP pairs specify connectivity.

Technical explanation. sketchSky(), importConstellations(), skyStep(), plot.skyscapeR.horizon().

16.4.4 Explore the Milky Way and reference circles

The traced band, its dark and bright structure, and the Galactic equator have different geometrical meanings. A sketch and a planisphere expose these as separate layer choices.

Technical explanation.

16.4.5 Compare twilight in opposite directions

Use the same saved sky for solar and antisolar views. Changing the azimuth limits changes the sampled direction. Disable the Moon to isolate the solar contribution and hold JD and display scale fixed.

Technical explanation. sketchSky(), plot.skyscapeR.horizon().

16.4.6 Capture a sky from Stellarium

A captured image reflects the external application’s state. Replotting a sector uses the existing raster, while stepping time requests a fresh capture. Record the external settings and the screenshot width.

Technical explanation. stellariumSky(), skyStep(), plot.skyscapeR.horizon().

16.4.7 Equinoctial full Moons and solstitial crescent crossovers

EFM pairs lunar and solar events. CC additionally applies the selected crescent and simulation gates. Inspect the diagnostics and the visibility margin when explaining why a particular day was selected.

Technical explanation. EFM(), CC().

16.4.8 A planisphere for the site’s latitude

The chart clips the epoch’s celestial sphere to the declinations that can rise at the specified latitude. Its geometric boundary and catalogue magnitude limit answer different questions from local detectability behind an actual skyline.

Technical explanation. planisphere().
