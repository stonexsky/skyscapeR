skyscapeR 2.0.9004

Find equinoctial full moonrises and moonsets

Description

Identify the near-full Moon whose rising or setting position crosses that of the Sun around the spring or autumn equinox.

Usage

EFM(
  year,
  loc,
  season = "spring",
  rise = TRUE,
  min.phase = 0.99,
  timezone,
  calendar,
  refraction,
  atm,
  temp
)

Arguments

year

Astronomical year or years. Can be either a single value (the year), Historical labels such as "3700 BC" are accepted by astroYear. two values (range of years), or a vector of years.

loc

This can be either a skyscapeR.horizon object, or a vector with the latitude, longitude and elevation of the site, in this order.

season

Either 'spring' or 'autumn'. Default is 'spring'.

rise

Logical to choose whether to calculate Equinoctial Full Moon rises or sets. Defaults to TRUE.

min.phase

Minimum illuminated fraction of the Moon, from 0 to 1. The default 0.99 means 99 percent illumination.

timezone

Timezone for civil timestamps. Use UTC or a fixed offset for dates before 1900. See time2jd for named zones and offsets.

calendar

Calendar for civil dates. Use "G" for Gregorian or "J" for Julian.

refraction

Logical. Apply atmospheric refraction. Defaults to the session setting in skyscapeR.vars.

atm

Atmospheric pressure in mbar. Defaults to the session setting in skyscapeR.vars.

temp

Air temperature in degrees Celsius. Defaults to the session setting in skyscapeR.vars.

Details

Silva and Pimenta (2012) identify the crossover by the first near-full Moon on the seasonal side of the Sun. Spring and autumn refer to the March and September equinoxes. At spring moonrise the lunar azimuth must exceed the solar azimuth, and at spring moonset it must be smaller. Autumn reverses both inequalities. Bearings are topocentric, clockwise from north.

The search runs chronologically from 60 days before to 65 days after the astronomical equinox. Moonrise is paired with the first sunrise on the same local civil date. Moonset is paired with the most recent sunset before it, considering the first solar centre crossing on the current and preceding local civil dates. A candidate without such a sunset is skipped. Local-day boundaries account for timezone changes, including daylight saving time. A coordinate vector specifies a level horizon. A horizon object supplies the horizon for both bodies. Illumination is tested at the lunar event itself. A date qualifies as soon as the illumination and strict bearing conditions both hold. A lower illumination threshold can select an earlier lunation. If no date qualifies the function reports the year and event and stops.

Dates and clock times use the supplied timezone and calendar. Changing the timezone can change which events share a civil date. Declinations use the package coordinate setting (topocentric by default). For comparison with Figure 3 of Silva and Pimenta, request geocentric declinations with skyscapeR.vars(dec="geo"). Event selection uses topocentric bearings in either output frame.

Value

A list with an Event label and Moon and Sun data frames. Each row gives year, date, time, azimuth and declination for the selected rising or setting event. Angles are in degrees.

Comparison with the original simulations

With the corrected preceding-sunset pairing, 2,562 of 2,568 moonsets in the supplied 1620–2047 series at latitudes 0, 60 N and 60 S agree within 0.02 degrees in lunar declination. The comparison uses a level horizon, longitude 0, elevation 400 m, UTC, Gregorian dates, geocentric declinations, refraction, pressure 1013.25 mbar, temperature 15 degrees Celsius and the default illumination threshold. Five remaining cases lie just above the 0.99 illumination boundary; one lies about 0.002 degrees beyond the azimuth crossover boundary. The original series selects the following morning in each case. Thresholds have not been tuned to reproduce those selections.

The original 40-degree N series retains systematic coordinate differences. Diagnostic comparisons suggest a different coordinate-conversion or timing convention, but the original settings have not been established. Agreement with these simulation tables is not independent observational validation. The paper does not specify all atmospheric settings; the values above describe this comparison, not confirmed settings of the original simulations.

Astronomical positions require Swiss Ephemeris files covering the epoch. We recommend installing swephRdata; see skyscapeR-package for setup.

Scope of the event model

The illumination fraction is a selection criterion, not a naked-eye detection model. The calculation does not include weather, sky brightness or extinction. It uses centre crossings rather than the first appearance of the upper limb. Only the first qualifying event is returned, so changes in illumination threshold, civil-day convention or horizon can change the selected lunation. Remaining differences from the original simulations are described above. Numerical precision does not establish agreement with a published distribution. Preserve all inputs when comparing series.
