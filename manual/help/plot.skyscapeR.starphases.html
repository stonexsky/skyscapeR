Function index · plot.skyscapeR.starphases() method

Plot seasonal stellar visibility

Description

Compare the seasonal visibility of one or more stars at the modelled site and epoch. Each result shows the stellar name, designation and epoch. To compare one star across epochs, compute a phase object for each year and pass the second object to plot as its second argument.

Usage

## S3 method for class 'skyscapeR.starphases'
plot(
  x,
  y,
  show.labels = TRUE,
  show.legend = TRUE,
  show.grid = TRUE,
  sort.by,
  pal,
  ...,
  layout = c("auto", "linear", "circular"),
  style = "publication-colour"
)

Arguments

x

A star phase result.

y

A second object of skyscapeR.starphases format or a list of skyscapeR.starphases objects for plotting (see Examples).

show.labels

Logical. Mark annual events for a single result in either layout. Defaults to TRUE.

show.legend

Show a legend for seasons present among the plotted stars (default TRUE). For circular plots FALSE also hides titles, site/epoch text and all layer or event callouts. The seasonal scale stays visible. Linear plots keep their data and event labels.

show.grid

Draw monthly dividers through each ring or strip. Defaults to TRUE. Set FALSE to omit the monthly divisions and retain the seasonal axis.

sort.by

Optional ordering by catalogue magnitude ("mag"), first R-only sample ("rise") or first S-only sample ("set") on the stored cycle. This is not sorting by the dated heliacal event. Missing classes are placed last; omission retains input order.

pal

Five colours in the order RS (rise and set), R (rise only), S (set only), V (curtailed passage) and I (arising and lying hidden). The default uses five colours from the plot style. Monochrome adds textures to distinguish the classes. Supply all five even when only some seasons occur.

...

Additional arguments to be passed to plot.

layout

"auto" and "circular" draw a single ring or concentric rings in input (or requested sort) order from the outside inward. Leaders connect the layer identifiers to their rings. Select "linear" for strips. Supply this argument by name.

style

Analytical display style, either "publication-colour" (default) or "publication-mono". Monochrome uses grayscale and preserves line styles.

Details

Read each colour as a daily model classification: visible rising and setting, rising only, setting only, visible without a qualifying near-horizon passage, or invisible. The function plots the stored phase sequence on a 365-day scale and can label seasons or display a legend. A single result defaults to a circular view, advancing clockwise from December solstice. Further results use concentric rings with one leader per displayed layer; optional sorting uses the stored apparent magnitude or seasonal onset. Changing the display does not recalculate the visibility thresholds. Use plot(first, list(second, third)) to compare results.

Value

Draws on the active graphics device and returns NULL invisibly.

Seasonal axis and comparison

The axis is a 365-sample synthetic solar-longitude cycle anchored at December solstice. Equinoxes and solstices mark quarter-cycle positions. The monthly dividers mark twelve equal intervals of 30 degrees in solar longitude, beginning at December solstice. For calendar dates use the underlying result's metadata$events$date.julian, as described in star.phases.

Objects may represent different stars, epochs, sites or model assumptions. Shared star, epoch and site appear once. Different epochs of the same star label individual rings or rows. Mixed comparisons identify both star and year. Hold the site, extinction and other inputs fixed for a controlled epoch comparison, or state their differences in the figure caption. Names on the supplied list can override the displayed star names. The legend contains only the union of season classes present in the plotted objects.

Event annotations use transitions between adjacent samples, including the last and first samples of the cycle. A season continuing through December solstice has no event at that boundary. Entry into and exit from I mark acronycal setting and heliacal rising; entry into and exit from V mark acronycal rising and heliacal setting. Constant classifications have no transition labels. A single ring labels each event by name on two lines just outside the rim. Its short leader meets the ring at the event's model day. A single ring shows the star, epoch and site in its centre. Rings for one star at several epochs show the star, designation and shared site in the centre, with a year for each ring. The circular layout labels the solstices and equinoxes outside its rim. Both layouts mark the event's model day, the last sample before entry into I or V, or the first after exit. The linear seasonal scale sits immediately below the lowest strip. Each quarter label aligns with its solstice or equinox across every row. Rising-event labels sit close above a single strip and setting-event labels close below it, leaving room for the seasonal scale where needed. Both layouts use the same sequence and colours; the circular layout makes the cycle boundary explicit. Labels wrap and shrink to fit; crowded comparisons need a larger device.

Validation

W01 checked season boundaries, event positions, quarterly landmarks and star, site and epoch labels in linear and circular layouts. See the W01 check in the technical manual.

Examples

## Not run: 
if (requireNamespace("swephRdata", quietly = TRUE)) {
  # Plot the seasonality of Aldebaran for 4001 BCE:
  s1 <- star.phases('Aldebaran',-4000, c(35,-8, 200))
  plot(s1) # circular by default
  plot(s1, layout="linear")
  # Plot seasonality of several stars
  s2 <- star.phases('Alnilam',-4000, c(35,-8, 200))
  s3 <- star.phases('Elnath',-4000, c(35,-8, 200))
  plot(s1, s2)
  plot(s1, list(s2,s3))
  plot(s1, show.legend=FALSE, show.grid=FALSE)
}
