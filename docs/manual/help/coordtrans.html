Function index · coordtrans() method

Transform azimuth densities into declination densities

Description

Estimate which declinations a measured bearing could indicate after allowing for uncertainty in both direction and horizon altitude.

Usage

coordtrans(
  pdf,
  hor,
  xrange,
  .res = 0.1,
  .prec = 0.1,
  .output.res = 0.01,
  verbose = TRUE
)

Arguments

pdf

A skyscapeR.pdf object created with az.pdf or a skyscapeR.spd object created with spd

hor

A shared skyscapeR.horizon or, for individual azimuth PDFs, a list of horizons in measurement order.

xrange

Array of values (min and max) for SPD when transforming a skyscapeR.spd object.

.res

Spacing of the declination calculation grid, in degrees. Default 0.1.

.prec

Azimuth integration spacing, in degrees. Default 0.1. Smaller values increase integration work. Must not exceed 540.

.output.res

Spacing of the returned declination grid, in degrees. Default 0.01. Coarser spacing reduces output size. All spacings must be positive finite scalars, and the returned grid must contain at least two points.

verbose

Logical. Display progress or informational messages. Default TRUE.

Details

A sightline has a distribution of possible bearings, and each bearing samples a potentially different part of the horizon. For every sampled bearing the function interpolates horizon altitude and uncertainty, maps an altitude range to declination and approximates the conditional declination distribution by a Gaussian. It weights that distribution by the azimuth density and integrates the product by the trapezoidal rule. All six az.pdf families supply these bearing weights. The Gaussian approximation here describes uncertainty in horizon altitude at a fixed bearing. An asymmetric or bounded bearing model can therefore produce a declination curve with a different shape or several peaks. A shared horizon can serve several observations, or a supplied list can represent their individual sites.

Density values are calculated at declination spacing .res, then linearly interpolated onto a grid with spacing .output.res. The upper calculation bound is evaluated explicitly if the step does not land on it, avoiding extrapolation at the tail. Linear interpolation preserves nonnegative calculated densities and avoids cubic-spline overshoot. Individual PDF outputs retain their existing area normalisation; SPD outputs retain their existing unnormalised transformation behaviour. Coarse calculation spacing can still miss narrow peaks; interpolation does not replace a resolution-convergence check. Azimuth integration uses a separate grid from -90 to 450 degrees with step .prec. For a distribution split across north, integration uses contiguous bearings around zero at the same spacing. The output grid starts at the lower bound and ends at the last full step within the upper bound. Refine the calculation grid to check that narrow features are resolved. Set atmospheric refraction, pressure and temperature with skyscapeR.vars before transforming. The values used are recorded in the returned PDF or SPD. All three spacings are stored in metadata$param. For a specified azimuth null tested in declination, use modelTest with azimuth inputs and hor. It repeats this individual transformation for each observed and simulated density; a direct declination model instead shifts or reconstructs declination densities.

The Gaussian uncertainty approximation uses the midpoint of declinations obtained at horizon altitude plus/minus four altitude standard deviations, with standard deviation equal to the absolute endpoint separation divided by eight. Reversed bounds are supported. Horizon uncertainties must be finite and nonnegative, and the profile must cover all input azimuths. For positive altitude uncertainties, direct quadrature is used if either transformed four-sigma endpoint reaches an absolute declination of 80 degrees or the endpoints coincide. It integrates the spherical transformation at 256 normal altitude quantiles. Bearing spacing is at most 0.025 degrees on this route and on skyline sections steeper than one degree of height per degree of bearing. The transform uses unrounded declinations internally. A zero altitude uncertainty remains unsupported. Nonfinite transformed bounds/densities and PDF outputs with no positive finite area also error. Positive but very narrow widths still require convergence checks; no minimum uncertainty is imposed.

Keeping the inputs. Save the original azimuth distributions and horizons in measurement order if you plan to draw the transformation curves or run a declination test. The result stores the numerical distributions and settings. The names in metadata$source.labels describe the inputs but cannot reconstruct them. See plot.skyscapeR.pdf and randomTest.

Value

A skyscapeR.pdf object for PDF input, or a skyscapeR.spd object for SPD input. Both contain metadata and data. PDF data are a list of data frames with declination x and density y; SPD data are a single such data frame. Metadata include the coordinate type, transformation settings, format version and descriptive source labels.

Validation

See the direct-propagation study below.

For a partial photograph the stored positive bearing density must lie within its photographed sector. H07 verified agreement with a complete skyline on the covered north-crossing cases and rejection of uncovered densities. See the H07 check in the technical manual.

Examples

Az <- az.pdf(az=c(87,93,90,110), unc=3)
hor <- createHor(az=c(0,360), alt=c(0,0), loc=c(35,-8,25)) # flat horizon
Dec <- coordtrans(Az, hor)
head(Dec$data[[1]])
Dec$metadata$source.labels
# Reduce stored output size without changing the calculation spacing:
Dec.coarse <- coordtrans(Az, hor, .output.res=0.1)
Dec.coarse$metadata$param

Validation studies
